# READOM Network — токен READ

Внутренняя крипто-сеть READOM: токен **READ** на off-chain реестре с хэш-цепочкой
(каждый блок содержит SHA-256 от своих данных и хэша предыдущего блока — подмена
любой записи ломает всю цепочку после неё). Реальный блокчейн пока не используется,
но формат готов к «якорению» в публичную сеть позже.

## Правила

| Действие | READ |
|---|---|
| Открытие кошелька (один раз) | +50 |
| Дочитанная глава (один раз на книгу × главу) | +5 |
| Лимит наград за чтение в сутки (UTC) | 50 |
| Пауза между наградами | 20 сек |
| Перевод / чаевые автору | 1 – 10 000 |

Адреса: `rdm1` + 38 hex-символов (`sha256(user_id)`; для авторов — `sha256("author:" + ключ)`).
Чаевые копятся на кошельке автора (адрес по имени автора) до появления привязки
автор ↔ аккаунт в Scriptorium.

## Устройство

- `src/integrations/readnet/engine.ts` — чистая логика: правила, хэширование, проверка цепочки (+ тесты).
- `src/integrations/readnet/network.ts` — два бэкенда с одним API:
  - **supabase** — общий серверный реестр, правила в SQL;
  - **local** — тот же движок в браузере (IndexedDB), включается автоматически,
    пока миграция не применена. Принудительно: `VITE_READNET_MODE=local|supabase`.
- `supabase/migrations/20261109120000_readom_network.sql` — таблицы, RLS, RPC-функции
  (`readnet_open_wallet`, `readnet_claim_reward`, `readnet_transfer`, `readnet_tip_author`, `readnet_stats`).
  Клиенты не пишут в таблицы напрямую; запись идёт только через функции под advisory-lock.
- UI: страница `/wallet` (баланс, адрес, перевод, история, обозреватель сети, проверка цепочки),
  баланс в верхней панели, награды за главы и кнопка «Поблагодарить автора» в читалке.

Константы и формат блока (`height|prevHash|kind|from|to|amount|memo|ts`) в `engine.ts`
и в SQL должны совпадать — клиент проверяет цепочку, полученную с сервера.

## Включение серверного реестра

```sh
supabase db push   # или примените SQL-файл миграции в Supabase Dashboard → SQL Editor
```

После этого клиент сам переключится на облачный реестр.
